# FkcGame

**多合一小遊戲插件**——設計成一個插件可以裝多款小遊戲，每款遊戲各自
一個獨立模組（`GameModule`），互不干擾。目前內建**日本立直麻將**跟
**UNO** 兩款遊戲，各自一個獨立章節，互不影響；之後要加新遊戲，同樣是
新增一個章節，不會動到既有遊戲的任何程式碼。

- **`/mahjong info`、`/uno info` 補上「當下是什麼牌」**：麻將現在會
  顯示最新一張棄牌（誰打的）跟目前的寶牌指標（日麻模式才有）；UNO
  會顯示目前牌面跟目前指定的顏色——之前這兩個指令完全沒顯示這些，
  只能靠當下跳出的訊息，滑過去就沒了。

- **新增即時側邊欄計分板**：**預設關閉，玩家要自己打 `/mahjong sidebar`
  （或 `/uno sidebar`，中文別名 `面板`/`側邊欄`）才會出現**，再打一次
  關掉，個人設定互不影響。開啟後畫面右側會顯示局數/輪到誰/手牌張數/
  最新棄牌/寶牌指標/分數（UNO 則是牌面/顏色/輪到誰/各家手牌張數/
  分數），跟著遊戲狀態即時更新，不用一直打 `/info` 查。
  **老實說這塊是我信心最低的部分**——不像遊戲規則邏輯我能在沙盒裡
  完整寫測試驗證，Scoreboard 顯示這塊沒辦法在沙盒裡實際跑起來看
  畫面對不對，Bukkit 這塊 API 這幾年也有過寫法上的變動。已經盡量選
  相容性最好、最不容易掛掉的寫法，但**請你實測後把畫面截圖給我看**。
  如果伺服器管理員想改成預設自動顯示，把 `config.yml` 裡的
  `sidebar-enabled` 改成 `true` 即可，改完 `/reload` 生效。

- **新開一局時，所有人立刻看到自己的起手牌**：之前只有莊家（先摸牌
  的人）會馬上看到手牌，其他 3 位玩家要等到輪到自己才第一次看到
  ——現在發完牌後，所有真人玩家都會立刻收到自己的起手牌訊息。

- **修掉一個嚴重的核心 bug：`discard()`(打牌)完全沒有檢查「現在真
  的輪到這個人」**。因為手牌的打牌按鈕會一直留在聊天記錄裡，玩家如果
  點到舊回合殘留的按鈕（或連點），不管當下輪到誰都會被接受處理，
  導致同一人連續打好幾張牌、遊戲順序整個亂掉（**這是實測時從伺服器
  log 抓到的真實案例，感謝回報**）。現在 `discard()` 跟 `declareAnkan()`
  （暗槓）都會先確認真的輪到這個人才處理，不是就直接忽略。
- **修掉吃碰槓胡叫牌視窗的殘留點擊問題**：連點 [碰] 之類的按鈕好幾次，
  舊的點擊有可能在下一次全新開啟的叫牌視窗誤判成有效回應。現在每次
  開啟叫牌視窗都有獨立編號，舊視窗的點擊會被直接忽略。

- **額外系統性檢查了整個麻將引擎的「動作型」方法**：確認自摸胡牌
  （`declareTsumo`）、換三張選牌都已經有正確的檢查；另外把「準備」
  指令也補上遊戲已開始就不該有效果的檢查（原本沒有實際危害，純粹
  避免顯示誤導訊息），UNO 那邊同樣補上。**現在有 7 套自動化測試、
  共 41 項驗證**，涵蓋叫牌視窗編號機制實際跑一場真的「碰」的情境
  （不是空測，是真的隨機發牌後製造出碰的機會去驗證）。

- **補上「真的胡牌」的測試**：之前的測試沒有一個真正走完整套自摸/
  榮和的勝利流程並驗證分數結算——現在直接操控牌局狀態，讓玩家真的
  自摸、真的被別人放槍胡牌，驗證分數正確轉移（含「總點數不變」的
  零和特性檢查）。過程中也抓到一個測試設計的誤區：**電腦玩家在架構
  上本來就不會被邀請進吃碰槓胡的叫牌視窗**（這是既有的已知限制，
  不是新發現的 bug），測試角色要設成真人才能正確驗證榮和流程。
  **現在共 9 套自動化測試、51 項驗證，全部穩定通過。**

- **新增 `/mahjong tenpai`(聽牌，別名 `聽牌`/`听牌`）**：主動查詢自己
  現在有沒有聽牌、聽哪些牌；如果剛摸完牌還沒打出，會列出「打出哪張
  牌可以聽牌、聽什麼」。**日麻、台麻都支援**（之前聽牌邏輯只綁定在
  立直提示上，台灣模式完全沒有聽牌資訊，這次一起補上，兩種規則共用
  同一個指令）。

- **重新登入時主動同步狀態**：之前斷線重連後，系統完全不會主動告訴你
  牌局進行到哪，要等到真的輪到你、或自己手動查 `/mahjong info` 才會
  知道最新狀態。現在重新登入的瞬間，如果你還在進行中的牌局裡，會
  自動收到「歡迎回來」訊息 + 目前輪到誰 + 最新棄牌 + 你的手牌，
  計分板也會重新顯示（UNO 同樣有這個機制）。

- **補上「牌山/牌堆剩餘幾張」的顯示**：麻將計分板、`/mahjong info`、
  重連歡迎訊息都會顯示牌山剩餘張數；UNO 的計分板、`/uno info`、重連
  歡迎訊息同樣會顯示牌堆剩餘張數。

- **這輪額外抓到兩個真正的核心 bug**（感謝你要求做更嚴謹的測試才挖出來）：
  1. **快速打出「不同」的牌**：如果打出一張牌後，吃碰槓胡的視窗還沒
     關閉，同一人這時候如果又打出另一張不同的牌，原本會被接受，把
     視窗狀態整個蓋掉、弄壞——現在會被正確擋下來。
  2. **修復過程中發現一個更深的既有 bug**：當沒有任何人能吃碰槓胡時，
     系統會直接跳過視窗、往下一位玩家推進，但漏了把視窗狀態標記
     重設，導致上面那個新加的保護機制**把後面所有打牌動作都擋死，
     整場遊戲直接卡死**。這個也修好了。
  - 兩個都額外寫了測試驗證，並且用電腦互打整場對局重新確認不會再
    卡死。過程中也修正了好幾個測試腳本本身設計不夠嚴謹的地方（配角
    玩家手牌沒控制好、誤用「假裝連線」玩家導致連鎖反應跑到預期外的
    地方），這些都不是遊戲引擎的問題，是我測試工具本身要抓穩。
  - **現在共 13 套測試、約 78 項驗證，反覆執行 20-30 次確認完全穩定，
    沒有任何隨機飄動的結果。**

- **修掉一個真的會讓指令崩潰的 bug（感謝實測回報 + 附上完整 log）**：
  在某些 Folia 伺服器上，`/uno start`（或麻將對應流程）會直接崩潰，
  原因是計分板功能用到的 Bukkit API（`getNewScoreboard()`）在該伺服器
  環境下不受支援，而**原本這段程式碼完全沒有防呆包裝，例外直接往外
  傳，把整個開始遊戲的流程中斷在一半**。現在計分板相關的所有操作都
  包進防護網——就算所在的伺服器不支援這個功能，也只會自動安靜停用
  計分板本身，**絕對不會影響麻將/UNO 其他功能正常運作**，只會在
  伺服器 log 印一則警告訊息說明。順便發現並修正了程式碼裡的預設值
  跟 `config.yml` 寫的預設值對不上的問題（config 說預設關閉，程式碼
  備用值卻是開啟）。

  **如果你伺服器上的 `config.yml` 是舊版本（沒有 `sidebar-enabled` 這
  個設定項目），麻煩換新版 jar 後同時也更新 `config.yml`**（或直接刪除
  舊檔讓它自動重新產生新的預設檔），不然舊設定檔仍然會讓計分板功能
  被觸發到（雖然現在已經不會再讓整個指令崩潰了，只是會多印一則警告
  訊息，不影響遊戲本身）。

- **修掉 UNO「喊UNO」洗版 bug**：`[喊UNO]` 按鈕連點好幾次，原本會
  重複廣播「XXX 喊了 UNO！」訊息，把聊天室洗版（感謝截圖回報）。現在
  只有第一次真正喊出來才會廣播，之後重複點擊會靜默忽略。

- **修掉一個嚴重 bug：台數/翻數不足時，自摸會誤把整局當流局重開**
  （感謝實測回報 + log，多位玩家反映「無法自摸」才挖出來）。原本
  `[自摸胡牌]` 按鈕顯示的判斷只看「牌型形狀對不對」，沒有檢查夠不夠
  最低台數/翻數；玩家點下去後，系統才在更深層發現台數不足，但處理
  方式錯誤地把整桌強制當成流局重新開局，完全沒有清楚告訴玩家「你
  這樣不夠台，不能胡」。現在按鈕顯示跟實際判定改成同一套完整標準
  （牌型 + 最低台數/翻數），台數不足時只會清楚提示那位玩家、遊戲
  正常繼續，不會再牽連全桌重開。榮和的按鈕顯示、電腦玩家的自摸判斷
  也一併修正。

- **`reload` 補上主控台紀錄**：之前只有聊天室回覆訊息，主控台完全
  沒有任何反應，看起來像沒作用。現在會在伺服器 log 印一行「config.yml
  已由 XXX 重新載入」，方便確認、也方便管理員稽核誰用過這個指令。

- **針對「打到一半突然不能吃碰」加了更全面的防護**：這很可能是計分板
  崩潰問題的另一種表現形式——`broadcast()`（幾乎每個遊戲事件都會
  呼叫）是在**打牌訊息廣播出去、叫牌視窗真正開啟之前**先執行的，如果
  廣播過程中有任何未預期的例外（例如計分板 API 出問題），會讓整個
  打牌動作中斷在一半，叫牌視窗完全沒機會開啟——玩家看起來就會像是
  「突然不能吃跟碰」，而且往往從那之後每次打牌都會一直發生。雖然
  計分板本身已經有防護了，這次額外在 `broadcast()` 這一層**再加一層
  保險**，不管未來任何原因讓這段流程出錯，都保證不會讓打牌動作本身
  被中斷、叫牌視窗一定會正常開啟。寫了測試直接模擬「計分板故障時
  打牌+碰還能不能正常運作」，確認沒問題。

## 本輪修正（重要，先看這裡）

- **新增 TAB 自動補全**：打指令時按 Tab 鍵會自動列出可選項（子指令、
  在線玩家名稱、手牌裡實際有的牌），不用整串手打或硬記語法。
- **新增排行榜**：`/mahjong rank`（可加 `riichi`/`taiwan` 指定規則）、
  `/uno rank`，依累積點數排名。**有電腦玩家的桌子完全不計分**，詳細
  防刷分設計見下方「排行榜與防刷分」章節。

- **手牌/牌面顯示改回純中文文字**：原本用的 Unicode 麻將牌符號，Minecraft
  預設字型不支援，會顯示成空白方塊。現在全部改成 `3萬`、`3筒`、`3條`、
  `東`、`南`、`西`、`北`、`白`、`發`、`中`、`花梅`、`花蘭`、`花竹`、
  `花菊`、`花春`、`花夏`、`花秋`、`花冬` 這種可讀文字，赤寶牌會多顯示
  「寶」字（例如 `5萬寶`）。UNO 也一樣改成純中文（`紅5`、`綠跳過`、
  `萬能+4`），並改用真正的 Adventure API 上色（不是塞失效的 `&`/`§`
  代碼進文字裡，那樣只會讓代碼字元原封不動印出來，這是先前的錯誤）。
- **修掉一個會導致遊戲直接崩潰的 bug**：`/mahjong leave`、`/uno leave`
  原本在遊戲進行中也能執行，會把玩家從名單移除、把「輪到第幾位」的
  編號弄亂，導致 `IndexOutOfBoundsException` 崩潰。現在**遊戲進行中
  禁止離開**，會提示等對局結束或請桌主解散牌桌。
- **單純斷線不用擔心**：只要沒有主動打離開指令，遊戲設計上本來就會把
  斷線玩家當作「暫時離線」處理（自動幫他摸牌/打牌，跟電腦玩家類似），
  不會把他真的踢出名單，所以不會觸發上面那個崩潰。
- **新增 `/reload`**（`/mahjong reload` 或 `/uno reload`，需要 OP 或
  `mahjong.reload`/`uno.reload` 權限）：改完 `config.yml` 後打這個
  指令就會生效，不用重啟伺服器。**只影響之後新開的牌桌**，正在進行
  或等待中的桌子不會回頭套用新設定。

## 架構速覽（給之後要加新遊戲的人看）

- 主插件類別 `com.fkc.game.FkcGamePlugin`，只負責啟動/關閉時逐一呼叫
  每個已註冊的 `GameModule`
- 每個遊戲各自一個套件，例如麻將在 `com.fkc.game.mahjong.*`，實作
  `com.fkc.game.core.GameModule` 介面（`onEnable(Plugin)` / `onDisable(Plugin)`）
- 每個遊戲的 `config.yml` 設定放在自己的頂層區塊底下（例如麻將的設定
  都在 `mahjong:` 這一段），避免以後設定互相打架
- 要加新遊戲：寫一個新套件、實作 `GameModule`、在 `plugin.yml` 加上
  新指令區塊、在 `FkcGamePlugin.createModules()` 多加一行註冊——不用
  動到既有遊戲的任何程式碼

## 麻將（Mahjong）

自己刻的日本立直麻將，支援吃碰槓胡的即時提示（點聊天室按鈕，或直接
打字操作），規則核心（役種/翻符計算）**完全自己實作，不依賴任何外部
函式庫**，確保編譯穩定不會卡在對不上的第三方 API。

## 指令（`/mahjong`、`/mj`、`/majiang` 都可以用，中英文皆可）

### 大廳階段

| 解散牌桌 | `destroy`（桌主限定） | `解散` |
| 查看資訊 | `info`（進行中會顯示目前輪到誰） | `查看`、`資訊` |
| 列表 | `list`（依建立時間排序） | `列表`、`清單` |

直接解散不用確認。

### 遊戲中操作

不用手動打指令——摸牌後系統會自動在聊天室列出手牌，每張牌都是可以
直接點擊的按鈕；輪到別人打牌時，如果你能吃/碰/槓/胡，系統也會自動
跳出可點擊按鈕，限時內（預設 15 秒，`config.yml` 可調）沒回應就視為
跳過。

**點擊不方便時（例如手機版）也能直接打字**，支援簡短指令：

| 動作 | 簡短打字 | 完整寫法 |
|---|---|---|
| 打牌 | `/mj 打 5m` | `/mahjong action discard 5m` |
| 立直 | `/mj 立直 5m` | `/mahjong action riichi 5m` |
| 自摸 | `/mj 自摸` | `/mahjong action tsumo` |
| 暗槓 | `/mj 暗槓 5m` | `/mahjong action ankan 5m` |
| 榮和 | `/mj 胡` | `/mahjong action call ron` |
| 碰 | `/mj 碰` | `/mahjong action call pon` |
| 明槓 | `/mj 槓` | `/mahjong action call minkan` |
| 吃 | `/mj 吃 [編號]` | `/mahjong action call chi [編號]` |
| 跳過 | `/mj 跳過` | `/mahjong action pass` |
| 換牌選取 | `/mj 換牌 5m` | `/mahjong action exchange 5m` |
| 確認換牌 | `/mj 確認換牌` | `/mahjong action exchangeconfirm` |

也支援對應英文（`pon`/`ron`/`kan`/`chi`/`pass`/`tsumo`/`discard`/`riichi`/`ankan`）。

牌名輸入格式：`5m`/`5萬`、`3p`/`3筒`、`7s`/`7條`、`東`/`南`/`西`/`北`、
`白`/`發`/`中`，或原始數字編號 0–33（按鈕背後用這個）。

## `/mj 查看` 顯示的內容

1. 牌桌內所有玩家名單（等待中顯示準備狀態／進行中顯示點數）
2. 你自己的手牌
3. 每位玩家已叫出的明牌組（碰/吃/槓，同桌公開可見）
4. 每位玩家的棄牌河（依時間順序，同桌公開可見）

## 換三張

桌主開桌後、開始前用 `/mahjong exchange` 切換。開啟後每局發完 13 張牌，
先進入換牌階段：點擊手牌選 3 張（再點一次取消），選滿後點
`[確認換牌]`，全員確認後自動執行交換（固定往下家換），才開始正式對局。

**簡化之處**：固定方向（不會逐局輪替），且點擊介面沒辦法精準選到
「這一張」而非「另一張同款」重複牌（只能選到花色數字），多數情況
不影響，極少數想保留其中一張同款牌的情境會不夠精準。

## 對局結束後

公告名次、廣播結果後，**倒數 5 秒**，牌桌自動重置回「等待中」：所有人
的準備狀態、手牌、明牌組、棄牌河、點數（重設回起始分數）全部清空，
同一批玩家不用重新加入，直接 `/mahjong ready` 準備下一場即可。

**最終點數只是遊戲內部計分，不會換算成任何伺服器貨幣或實際獎勵**，
跟開桌費（另一個獨立設定）沒有關係。

## `config.yml` 完整設定

麻將的設定全部放在 `mahjong:` 這個頂層區塊底下（前面提過的多遊戲
架構設計，以後別的遊戲設定不會跟這個打架）：

```yaml
mahjong:
  rules:
    game-length: EAST_ONLY          # EAST_ONLY(東風戰) 或 EAST_SOUTH(東南戰)
    min-han: 1                      # 最低幾翻才能胡牌
    red-five-count-per-suit: 1      # 每色赤五張數，0 = 不用赤寶牌
    thinking-time-seconds: 15       # 吃碰槓胡提示視窗秒數
    starting-score: 25000           # 每人起始點數
    exchange-three-default: false   # 開桌預設是否開啟換三張

  # 公開資訊（誰打牌/碰吃槓/胡牌/開局/流局/結束/換三張）要不要「額外」
  # 廣播給全伺服器所有在線玩家。同桌玩家永遠都看得到，這裡只控制要不要
  # 順便讓沒加入牌桌的其他人也看到，每種訊息類型獨立開關。
  # 手牌內容本身完全不受這裡影響，永遠只有玩家自己看得到。
  broadcast-to-server:
    round-start: false
    discard: false
    call: false
    win: false
    draw: false
    game-end: false
    exchange: false

  # 等待中的牌桌超過幾分鐘沒開始就自動解散（避免列表堆積殭屍桌）
  table-idle-timeout-minutes: 5

  # 誰能開桌、開桌要不要收費
  table-creation:
    permission: ''    # 需要的權限節點，留空 = 所有玩家都能開桌
    fee: 0             # 開桌費（透過 Vault 經濟系統扣款），0 = 免費，沒裝
                        # Vault 這個設定會被忽略，開桌一律免費
```

改完存檔後需要**重啟伺服器**讓設定生效（尚未實作 `/mahjong reload`）。

## 已知的簡化 / 沒做的部分（誠實列出，避免你誤會是「完全無誤」）

- **役滿只做了國士無雙**，沒有實作四暗刻、大三元、字一色、清老頭、
  綠一色、四槓子、九蓮寶燈這些更少見的役滿。
- **不判定振聽（furiten）**。
- **平和的判定是簡化版**：只檢查「全部是順子、對子不是役牌」，沒有
  嚴格驗證聽牌形狀一定要是兩面聽。
- **一炮多響（多家同時榮和）簡化成只有第一家胡牌算數**。
- **電腦玩家(bot) 很陽春**：只會自動摸牌、打出剛摸到的牌，不會宣告
  立直、不會吃碰槓，純粹是湊桌用，不是真的 AI 對手。
- **流局（牌山摸完）沒有做「聽牌罰符」的結算**，只是單純換莊。
- **沒有補花**：這是台灣麻將（16張牌制）的機制，日本立直麻將本來就
  沒有花牌，故意不做。
- **牌桌/座位/牌面純聊天室文字呈現**，沒有 3D 模型或實體位置，玩家
  不用真的走到某個地方，純粹靠聊天訊息 + 點擊按鈕互動。

如果你實際玩過後覺得某個役種算錯了，把當下的手牌截圖 + 系統顯示的
翻符結果貼給我，我可以直接對照 `HandEvaluator.java` 幫你確認邏輯。

## 台灣麻將（十六張）

開桌時可以選擇規則：

```
/mahjong create           → 預設日本立直麻將
/mahjong create riichi    → 明確指定日麻
/mahjong create taiwan    → 台灣麻將（十六張），也接受 台麻/台灣/十六張
```

兩種模式共用同一套牌桌引擎（吃碰槓的呼叫視窗、廣播分類、對局結束
倒數重置等機制全部通用），差異在牌型跟計分邏輯：

- **16 張起手牌**（日麻是 13 張），胡牌形是 **5 組面子 + 1 對眼**（日麻是 4 組）
- **144 張牌**（136 張基本牌 + 8 張花牌：春夏秋冬、梅蘭竹菊），**沒有赤寶牌**
  （日麻的赤五寶牌是日麻專屬概念，台灣模式不使用）
- **補花**：摸到花牌不能當手牌用，自動放到你的「花牌區」亮出來，
  再補摸一張正常牌頂替（如果補到的還是花牌，會一直補下去直到摸到
  正常牌為止）
- **沒有立直、一發、寶牌**這些日麻專屬概念，台灣模式完全不會出現
  這些提示
- **算台不算翻符**：門清、自摸、平胡、對對胡、三/四/五暗刻、混一色/
  清一色/字一色、小/大三元、小/大四喜、風牌/箭牌刻子、槓、花牌
  （含花槓、滿花）——這套核心邏輯（`TaiwanHandEvaluator.java`）已經
  實測驗證過（含電腦互打整場對局的自動化測試），過程中抓到並修好一個
  真的重複計算台數的 bug（五暗刻情況下對對胡被算兩次）

**誠實聲明：台灣麻將的台數表沒有全國/全地區統一標準**，這裡用的是
從多個公開參考資料整理出來的「常見版本」，**不是唯一正確答案**。如果
你們牌桌習慣的台數不一樣，直接改 `config.yml` 的
`mahjong.taiwan-rules.tai.*` 底下的數字就好，不用重新編譯。

**明確沒有實作的部分**：十六不搭（一種特殊散牌型）、全求人/半求人/
不求人（併入門清/自摸處理，沒有拆成獨立分類）、七對子的台灣變體
（台灣十六張沒有標準的七對子玩法，故意不做）。

## 排行榜與防刷分

三款玩法（UNO、日麻、台麻）**各自獨立一份排行榜**（分數量級完全不同，
不能放在一起比）。存檔方式是純文字的 `.properties` 檔案（存在插件的
資料夾底下，`leaderboard-uno.properties`、
`leaderboard-mahjong-riichi.properties`、
`leaderboard-mahjong-taiwan.properties`），伺服器重啟資料不會不見，
**不用額外裝資料庫**。

指令：
```
/mahjong rank            查看日麻排行榜（預設）
/mahjong rank taiwan     查看台麻排行榜
/uno rank                查看 UNO 排行榜
```

### 有電腦玩家的桌子，一律不計分

三款遊戲都一樣，只要牌桌裡有任何一位電腦玩家，整場結束後**完全不會
寫入排行榜**——電腦對手太容易預測、太好贏，讓它算分數等於開洞讓人
刷分。

### 麻將（日麻/台麻）：靠「零和」天生防刷

麻將記錄的是**這場淨輸贏**（結束分數 − 起始分數），不是最終分數本身。
因為麻將本來就是零和遊戲——贏家拿走的點數，一定等於在場其他人合計
損失的點數，**總量不變**。這代表兩個帳號對打，想讓其中一個刷分，
另一個必須真的等量虧分數，不是無成本的操作，天然就有防呆效果。

另外還加了**每人每天最多計入幾場**的上限（`config.yml` 可調，預設
20 場），擋掉用腳本 24 小時刷分這種暴力手段。

### UNO：額外補了兩道防線（因為天生不是零和）

UNO 跟麻將不一樣——原本的設計裡，**沒贏的玩家分數不會被扣**，代表
「故意放水讓某人一直贏」在遊戲本身的規則裡完全沒有成本，這是設計
麻將排行榜時發現的一個潛在漏洞，額外用兩個設定補上：

1. **強制最低人數**（預設至少 3 位真人才計分）：協調 2 個帳號互相
   放水很容易，協調 3 個以上帳號一起配合，成本跟被發現的風險都高
   很多。
2. **沒贏的玩家排行榜倒扣一點分數**（預設 -20）：讓「一直故意輸給
   某人」這件事變成有代價的選擇，不是免費的。

**老實說，這兩道防線不是完美解**（真的鐵了心想刷分，加上足夠多的
時間跟帳號還是能刷），但比完全沒有防護好很多，也是我能想到、合理
可實作的折衷方案。如果你觀察到有人在刷分，`min-players-for-ranking`
跟 `loser-penalty` 兩個數字都可以直接調整（例如提高最低人數到 4、
提高倒扣分數），改完 `/uno reload` 就生效。

## Folia 安全性設計

- 完全沒有用 ProtocolLib / 封包攔截，純粹用聊天訊息 + Adventure 的
  可點擊 Component 做互動，不會踩到 ItemsAdder 攔截器那類老問題。
- 計時（叫牌限時視窗、對局結束後的重置倒數、閒置牌桌檢查）全部用
  `GlobalRegionScheduler`，只操作插件自己的記憶體資料，不直接碰任何
  實體，安全。
- 遊戲邏輯本身是純粹的資料運算（發牌、算牌、算分），不牽涉任何
  Minecraft 世界/實體操作。

## 規則範圍

- 標準 108 張牌（4色 × 0-9數字牌 + 跳過/反轉/+2，各色各2張，加上4張萬能+4張萬能+4）
- 2-6 人（含電腦），起手牌 7 張（可調）
- 兩人局的「反轉」照官方規則等同「跳過」（自己再出一次）
- 起始牌如果翻到萬能+4會重新洗回牌堆重翻；翻到其他特殊牌一樣會套用效果
- 一輪結束（有人出完手牌）：贏家拿到其他人手牌點數總和（數字牌算面值、
  功能牌20分、萬能牌50分），累積到設定的目標分數（預設500）結束整場
- 電腦玩家會照規則自動出牌（能出就出，不能出就摸牌、摸到能出的會出，
  不會宣告 UNO 也不會抓人，純粹湊桌用）

## 已知簡化

- **沒有實作「不當出牌+4挑戰」機制**：正式規則裡，如果對手出萬能+4時
  你手上其實有能出的同色牌，可以挑戰他出牌不合法；這裡沒做，萬能+4
  可以隨時自由使用。
- **UNO 喊叫沒有嚴格計時窗口**：只要手牌是 1 張、還沒喊過 UNO，隨時
  都能被別人抓包，不是「限時幾秒內」才抓得到。
- **這套核心邏輯已經實測驗證過**：deck 建構、canPlay 出牌合法性判定、
  分數計算、卡牌解析、以及讓電腦互打一整場到封頂分數的完整流程，全部
  跑過自動化測試確認沒有崩潰或卡死。
